# Занятие 7: сценарий на 85 минут

Номера относятся к `lesson7_fixed.pptx` из 66 слайдов. Это заметки преподавателя;
на слайдах и в Go-комментариях находятся объяснения и контракты для учащегося.
Не нужно последовательно показывать все 66 слайдов или набирать пять сортировок.

## Подготовка

Go 1.22.x, открытый корень classroom7. Заранее выполнить `make ci` и
`make bench-all BENCHTIME=20ms BENCHCOUNT=3`. Полная матрица benchmark не нужна
для ожидания на уроке: результаты находятся в `docs/benchmarks/`.

В этом архиве MP4 нет. Имена и секунды роликов из прежних слайдов исключены.
Для показа шагов доступны реальные Go trace и редактируемые схемы презентации.
Если позже добавлены видео, сначала отдельно проверьте их имена и содержимое;
счётчик кадров или шагов в ролике не является измерением скорости Go.

## Поиск: live coding и контроль границ

Открыть `internal/search/search.go`, функцию `SearchInsert`. Эталон уже есть
в проекте: для live coding достаточно восстановить её тело в том же файле,
не создавать второй пакет или отдельную копию проекта. Тесты не менять.

Перед кодом спросить: что вернуть для `[1,2,2,2,5]`, target=2? Ответ — 1.
Для target=8 ответ 5, это допустимая позиция вставки, а не индекс чтения.
Ввести полуинтервал `[left,right)`, объяснить строгое сокращение диапазона.

```bash
go test ./internal/search -run TestSearchContracts -v
make run-02_search
make run-03_maps
```

Ожидаются зелёные контракты: nil, пустой вход, края, отсутствие, повторы и
экстремальные int. `BinarySearch` может вернуть любое совпадение,
`SearchInsert` и `slices.BinarySearch` возвращают нижнюю границу.

## Три простые сортировки

Слайд 35: остановиться после обмена 5 и 1. Какая пара следующая? 5 и 4.
После полного прохода 5 окончательно справа. Если обменов нет, Bubble завершится.
Слайд 36: отсутствие обмена на одной позиции не доказывает готовность хвоста
Selection. Слайд 38: current=3 хранится отдельно, пока сдвигаются 7 и 4.

```bash
make run-05_simple_sorts
go test ./internal/simplesort -v
```

На входе `[5 1 4 2]` ожидаются Bubble 6 сравнений / 8 записей,
Selection 6 / 4 и Insertion 6 / 7. Это счётчики реализации, не benchmark.
Сравнить те же алгоритмы на sorted: Selection по-прежнему делает n(n−1)/2
сравнений, Bubble и Insertion используют готовый порядок.

## Merge и Quick: паузы в визуализации

Merge, слайд 41: сначала остановиться на двух отсортированных сериях
`[1 5]` и `[2 4]`. Спросить, откуда берётся следующий элемент результата.
Слайд 43: при равных ключах 1A / 1C первой должна идти A.

```bash
make trace-mergesort
go test ./internal/mergesort -run TestMergeStability -v
```

Quick, слайды 49–50: перед чтением 9 попросить назвать store и scan.
После обработки 2 имеем store=1, scan=2, values=`[2 7 9 3 5]`.
Пауза перед финальным обменом pivot: его окончательная позиция будет 2.
Слайд 53: предсказать сравнения на sorted длины 5 — 4+3+2+1=10.

```bash
make trace-quicksort
go test ./internal/quicksort -run TestLastPivotDegeneration -v
```

Для debugger открыть `cmd/07_benchmark_debug`, поставить breakpoint на цикле
в `partition`, добавить `values`, `scan`, `store`, `pivot`, `left`, `right`.
Пошаговый маршрут по двум IDE — в [debug-guide.md](debug-guide.md).
Debugger исследует живое выполнение; trace копирует историю. Ни тот ни другой
не должен попадать в измеряемый benchmark.

## Короткий benchmark в классе

```bash
go test ./internal/benchmarkdebug -run '^$' \
  -bench '^BenchmarkSort/copy-sort/(merge|quick|slices)/random/n=512$' \
  -benchmem -benchtime=20ms -count=3 -cpu=1
```

Вопрос: куда попадает выделение Merge-буфера? В измеряемый алгоритм.
Вопрос: почему B/op=0 не означает отсутствие памяти? Work подготовлен заранее,
а рекурсивный стек не является новым heap-буфером каждой итерации.
Объяснить, что короткий замер шумный. Для практического вывода нужны более
длинные повторы на машине учащегося, одинаковый сценарий и учёт подготовки.
