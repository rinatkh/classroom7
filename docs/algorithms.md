# Поиск и сортировка: контракт перед кодом

`n` — число элементов, `q` — число запросов, `k` — число разных ключей/размер диапазона (указан в строке). Оценки относятся к обычному алгоритму; сохранённая история trace требует отдельной памяти. Средние случаи требуют предположений о распределении входов: это не гарантия для каждого вызова.

## Поиск

| Функция / структура | Предусловие и результат | Лучший / средний / худший | Доп. память |
|---|---|---|---|
| `LinearSearch` | Любой срез; первое совпадение, иначе `Index=-1, Found=false` | O(1) / O(n) / O(n), среднее при равновероятном положении | O(1) |
| `BinarySearch` | Неубывающий срез; любое совпадение, иначе -1/false | O(1) / O(log n) / O(log n) | O(1) |
| `SearchInsert` (lower bound) | Неубывающий срез; первая позиция >= target, либо n | O(log n) во всех трёх случаях при n>0 | O(1) |
| `slices.BinarySearch` | Неубывающий срез; нижняя граница и found | O(log n) для реализации Go 1.22 | O(1) |
| `BuildFirstIndex` + `Lookup` | Любой срез; первый исходный индекс по ключу; -1/false при отсутствии | Построение O(n), запрос ожидаемо O(1); спецификация Go не даёт гарантии худшего времени | O(n) с текущим capacity hint |

Пустой вход завершается за O(1). В `BinarySearch.Comparisons` считается одна проверенная середина, даже если ветвление использует два сравнения int. Счётчик полезен для рассуждения о росте, но это не число инструкций CPU.

Полуинтервал `[left,right)` уменьшается при `left=middle+1` или `right=middle`. Нельзя смешивать его с включённой правой границей. При повторах обычный BinarySearch не обещает первую позицию; lower bound обещает. Поиск не меняет вход. Не сортируйте его внутри функции: это меняет исходные индексы и стоимость операции.

### Один запрос или серия

| Подход | Вся работа для несортированного входа |
|---|---|
| q линейных поисков | O(qn) в худшем случае; без отдельной подготовки |
| Копия + сортировка + q бинарных | O(n log n + q log n), O(n) для копии; индекс уже в отсортированной копии |
| Индекс + q lookup | ожидаемо O(n+q), O(n) для map; индекс может хранить исходную позицию |

Для единственного запроса подготовка часто дороже прохода. Для многих запросов она может окупиться. После изменения данных индекс надо поддерживать или строить заново. В [benchmark-guide.md](benchmark-guide.md) есть измерения всех трёх сценариев.

## Основные сортировки

| Алгоритм | Лучший | Средний | Худший | Доп. память | Устойчивость | На месте |
|---|---|---|---|---|---|---|
| Bubble, early exit | O(n) | O(n²) | O(n²) | O(1) | Да, строгое `>` | Да |
| Selection, обмен | O(n²) | O(n²) | O(n²) | O(1) | Нет | Да |
| Insertion | O(n) | O(n²) | O(n²) | O(1) | Да | Да |
| Merge из classroom | O(n log n) | O(n log n) | O(n log n) | O(n) буфер + O(log n) стек | Да, при равенстве слева | Нет, нужен второй массив |
| Quick, последний pivot | O(n log n) | O(n log n) | O(n²) | Стек: обычно O(log n), худшее O(n) | Нет | Да, со стеком |
| `slices.Sort`, Go 1.22 | O(n) на уже упорядоченном входе | O(n log n) | O(n log n) | O(log n) стек, без буфера n | Нет | Да, со стеком |

Строка `slices.Sort` описывает реализацию Go 1.22 (pdqsort с ограничением плохих разбиений и heapsort fallback), а не вечный контракт всех версий. Для записей с требованием устойчивости в рабочем коде есть `slices.SortStableFunc`; для обучения — наш `mergesort.SortFunc`. Внутри учебных сортировок нет вызовов готовой библиотечной сортировки.

### Механика, остановка и выбор

- **Bubble**: проход двигает максимум вправо; `end` уменьшается, отсутствие обменов завершает алгоритм. На sorted — один проход; на reverse — квадратично. Полезен для обучения соседним обменам; не выбирайте для большого массива.
- **Selection**: выбираем минимум хвоста, один обмен на позицию. Остановка — хвост длиной один. Даже sorted требует n(n−1)/2 сравнений; reverse не спасает. Учебный вариант с малым числом записей, не универсальная быстрая сортировка.
- **Insertion**: сохраняем current, сдвигаем строго большие, вставляем в готовый префикс. insert уменьшается до нуля либо до первого не большего значения. Sorted — O(n), reverse — O(n²). Точнее стоимость O(n+I), где I — число инверсий; слова «почти отсортировано» сами по себе не гарантируют O(n).
- **Merge**: две половины размера меньше n, базовый случай <2; merge каждый раз записывает очередной элемент, пока диапазон не заполнен. Один буфер выделяется на весь запуск. Sorted и reverse здесь всё равно O(n log n): оптимизация пропуска слияния сознательно не добавлена. Полезен для устойчивости и гарантии времени; не выбирайте при запрете массива O(n).
- **Quick**: partition ставит pivot на место; рекурсия исключает его, заканчивается при left>=right. Balanced даёт log n уровней. Sorted/reverse/all equal с последним pivot дают ровно n(n−1)/2 сравнений в нашей реализации; такие входы ограничены в benchmark. Полезен для изучения разбиения; не выдавайте этот вариант за промышленный `slices.Sort`.
- **slices.Sort**: обычный выбор для []int в прикладном Go. Не сохраняет равные записи в исходном порядке; код библиотеки не обязан повторять учебную Quick Sort.

## Дополнительные семейства

| Семейство | Время | Память | Условия и ограничения |
|---|---|---|---|
| Heap Sort | O(n log n), у простого варианта на одинаковых ключах возможен лучший O(n) | O(1) для итеративной heapify | Неустойчива; подробно на занятии 9 |
| Counting Sort | O(n+k) | O(k), для устойчивого вывода O(n+k) | k — небольшой известный диапазон; счётчики не подходят огромному разреженному диапазону |
| LSD Radix Sort | O(d(n+b)) | O(n+b) | d разрядов, основание b; нужны устойчивые проходы, порядок знаковых чисел обрабатывается отдельно |

Эти семейства даны для сравнения условий, а не как новые реализации занятия 7.

## Мини-задачи после примера

1. Какой индекс нужен при `[2,2,2]`: любое совпадение или самое левое? Выберите BinarySearch или lower bound.
2. Для одного отсутствующего значения в 100 несортированных числах сравните полный проход с подготовкой map.
3. Удалите запись из очереди: почему DeleteUnordered меняет контракт?
4. У записей `{Key:2, Tag:"A"}`, `{Key:2, Tag:"B"}` проверьте порядок после Merge; сравнение должно смотреть только на Key.
5. Предскажите число сравнений Selection и Quick на `[1,2,3,4,5]`, затем проверьте тестами со счётчиками.
