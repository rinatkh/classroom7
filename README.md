# Классная работа 7 — первые алгоритмы в Go

Материалы рассчитаны на первое знакомство с алгоритмами. Мы не начинаем с формул: сначала называем входные данные и одну простую операцию, затем считаем, сколько раз она выполнится при росте входа. После этого применяем тот же подход к поиску, вставке, удалению и сортировкам.

## Код и контракты

`internal/` содержит готовые алгоритмы, собственные тесты и общий набор входов
в `internal/testutil`. Комментарии фиксируют контракт, границы и инварианты;
подробные объяснения и типичные ошибки вынесены в [docs/algorithms.md](docs/algorithms.md).
Trace сохраняет снимки отдельно от обычного запуска и не входит в benchmark.

## Как читать benchmark

Команды без `-raw` запускают прежние `testing.B`, затем показывают **среднее
арифметическое по прогонам**: одна строка на алгоритм, сценарий, режим, `n`, `q`
и GOMAXPROCS. Таблицы идут по числовому размеру входа. `BENCHVIEW=compact`
показывает `last` для поиска и `random` для сортировок; остальные сценарии
измеряются и сохраняются в CSV, число скрытых строк указано в выводе.
`BENCHVIEW=full` показывает их все.

```bash
# Небольшой пример без ожидания полной матрицы:
make bench-search BENCHN=100 BENCHSCENARIO=last BENCHTIME=20ms
# Готовые структуры, затем отдельно стоимость подготовки и серии запросов:
make bench-search
make bench-search-build
make bench-search-queries
make bench-sort
make bench-structures
make bench-memory
make bench-all
# Полные таблицы и исходный формат testing.B:
make bench-search BENCHVIEW=full
make bench-search-raw
make bench-sort-raw
make bench-structures-raw
make bench-memory-raw
# Быстрая проверка всех веток, не устойчивый замер скорости:
make bench-all BENCHTIME=1x BENCHCOUNT=1
make help
```

В сырой строке `.../n=100  98816059  1.136 ns/op  0 B/op  0 allocs/op`:

- `n=100` — длина входного массива; `98816059` — **b.N**, автоматически
  выбранное число вызовов внутри одного прогона, а не длина или число сравнений;
- `-count=3` — три отдельных результата; в каждом могли быть миллионы вызовов;
- `ns/op` — среднее время одного полного измеряемого вызова в этом прогоне.
  На `n` его не умножают; для SearchQueries это вся серия из `q` запросов;
- `B/op` — выделенные heap-байты на вызов; `allocs/op` — число выделений.
  `0 B/op` не означает нулевую память входа, готового буфера или стека.

Новые запуски сохраняются в уникальном подкаталоге `bin/benchmarks/`:
`raw.txt`, `summary.csv` (все средние, медиана/min/max времени), `report.md`,
`environment.json` (версия Go, CPU/архитектура, параметры, состояние запуска).
`make clean` удаляет `bin`, поэтому нужные результаты предварительно скопируйте
или задайте `BENCHDIR=/путь/вне/bin`. В Git не попадают случайные локальные замеры.

Общий генератор: `internal/dataset.GenerateRandomSlice(n)` с seed 7.
`copy-sort` включает copy в готовый буфер, без выделения этого буфера;
`sort-only` исключает copy, но включает внутренние выделения алгоритма.
Bubble/Selection/Insertion/Quick ограничены `n≤512`; пропуски при большем `n`
подписываются как ограничение, а не как нулевое время.

В отчёте отдельно показаны расчётный размер **элементов входа** `n*sizeof(int)`,
измеренные allocation/op и теоретическая дополнительная память. Это три разных
величины. `middle` — конкретная цель, не средний случай. Числа зависят от CPU,
Go, кэша и сценария; benchmark не доказывает Big O. Подробности и импорт raw:
[методика](docs/benchmark-guide.md). Исторические медианы и новые реальные
примеры — в [результатах](docs/benchmarks/README.md).

## Режим отладки

Файл `docs/debug-guide.md` содержит одинаковый маршрут для GoLand и VS Code с Delve. Поставьте точку останова в `internal/quicksort/quicksort.go` на строке цикла `for scan := left; scan < right; scan++` и наблюдайте за `values`, `left`, `right`, `scan`, `store`, `pivot` и глубиной рекурсии.
